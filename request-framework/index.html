Request a framework
or language

CORAL's coverage grows through community requests. Use this page to submit a request for a new compliance framework, a new spoken/written language for manifests, or a new code language for test suites. All requests are public and tracked on GitHub.

Submit via GitHub

The preferred method. Open a Discussion in the Requests category using the template below. This lets the community weigh in and lets maintainers track progress transparently.

Open a Discussion

Submit by email

Prefer email? Send your request to request@coral-oss.dev using the same template below. Email requests are reviewed and, with your permission, posted publicly on GitHub to allow community input.

request@coral-oss.dev

Want to contribute the manifest yourself? If you're willing to author the YAML manifest for the framework you're requesting, your request will be prioritised. See the Contributing Guide for the manifest format and how to submit a pull request.

Template 1

Compliance framework or regulation

Use this template to request a new regulatory law (e.g. HIPAA, LGPD) or audit standard (e.g. ISO 27001, FedRAMP). Copy the block below and fill in your details.

framework-request.md Copy and fill in
Request type *
Framework / Regulation
Framework name *
e.g. HIPAA, ISO 27001, FedRAMP, LGPD, NIS2
Use the official name and acronym. If the framework has multiple versions, specify which (e.g. PCI DSS v4.0).
Governing body *
e.g. U.S. Department of Health & Human Services, ISO/IEC, AICPA
Jurisdiction *
e.g. United States (federal), European Union, Brazil, Australia
This becomes the JURISDICTION token in the reference ID — e.g. HIPAA.US.§164.312a
Authoritative source URL *
e.g. https://www.hhs.gov/hipaa/for-professionals/security/laws-regulations/index.html
Link to the official legal text or standard document. Government and standards body URLs preferred.
Spoken / written language of the official text *
e.g. English only / French and English (bilingual) / Portuguese
If the authoritative text is in a language other than English, note this. CORAL tracks which language is authoritative and which are translations.
Why does this matter to your project? *
Describe your use case. What industry are you in? What obligation does this framework place on your code?
Affected clauses or controls (optional but helpful)
e.g. HIPAA §164.312(a)(1) — Access control; §164.312(e)(1) — Transmission security
List the specific clauses most relevant to code-level compliance. This helps prioritise which controls to implement first.
Can you contribute the manifest? (optional)
Yes / No / Maybe with guidance
Requests with a willing author are prioritised. If yes, a maintainer will reach out to guide you through the manifest format.
Template 2

Spoken or written language

Use this template to request a new human language for CORAL manifests and reports — for example, Spanish, German, Portuguese, or Japanese.

Note on authoritative languages. When a law's official text is in a language other than English, CORAL marks it as authoritative and flags any other language as a community translation. Accuracy of non-authoritative translations is the responsibility of contributors, and CORAL includes a disclaimer in generated reports.

language-request.md Copy and fill in
Request type *
Spoken / Written Language
Language name *
e.g. Spanish (Castilian), Brazilian Portuguese, German, Japanese
Use the English name followed by the ISO 639-1 code — e.g. Spanish (es), Portuguese — Brazil (pt-BR).
ISO 639-1 / BCP 47 code *
e.g. es, pt-BR, de, ja
Frameworks affected *
e.g. GDPR (authoritative text available in this language), LGPD (primary language)
List the frameworks whose official authoritative text is available in this language, or for which you want a translated manifest.
Is this language authoritative for any framework? *
e.g. Yes — LGPD is authoritative in Portuguese / No — this is a community translation request
Can you contribute the translation? (optional)
Yes / No / Partial
Native speaker or legal professional contributions are especially valued. Translation PRs are subject to review by at least one other speaker.
Additional context (optional)
Any relevant notes about legal nuance, regional variants, or specific clauses you're aware of.
Template 3

Programming language or ecosystem

Use this template to request support for a new programming language or package ecosystem — for example, Python (PyPI), Ruby (Gems), or Java (Maven).

ecosystem-request.md Copy and fill in
Request type *
Programming Language / Ecosystem
Language / ecosystem name *
e.g. Python, Ruby, Java, Rust, .NET
Package manager *
e.g. pip / PyPI, Bundler / RubyGems, Gradle / Maven, Cargo, NuGet
Include both the tool (e.g. pip) and the registry (e.g. PyPI) if applicable.
Lock file format *
e.g. requirements.txt / Pipfile.lock, Gemfile.lock, pom.xml / build.gradle, Cargo.lock
CORAL parses lock files to resolve the full dependency tree. List the file format(s) we'd need to support.
Test framework(s) used in this ecosystem *
e.g. pytest, unittest / RSpec, Minitest / JUnit, TestNG / cargo test
CORAL generates compliance test stubs. Knowing the test framework helps us generate idiomatic output.
Compliance frameworks you need this for *
e.g. GDPR, HIPAA, SOC 2 — I'm building a Python service that processes health data
Can you contribute the ecosystem adapter? (optional)
Yes / No / Maybe with guidance
Ecosystem adapters are self-contained modules. If you can contribute, a maintainer will walk you through the interface.
